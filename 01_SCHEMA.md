## Table: `documents`

Each row in this table represents **one chunk** of a parent document. A single ingested document will produce multiple rows (one per chunk). Parent document identity is preserved via the `title` and `source` fields — all chunks from the same document share the same `title`.

### Field Reference

| Field | Data Type | Constraint | Default | Nullable | Description |
|---|---|---|---|---|---|
| `id` | `uuid` | PRIMARY KEY | `gen_random_uuid()` | No | Unique identifier for each chunk row. Auto-generated by Supabase on insert. |
| `title` | `text` | NOT NULL | — | No | Human-readable title of the parent document. Required at intake. All chunks from the same parent share this value. Used for source citations and for the delete-before-reingest deduplication strategy. |
| `content` | `text` | NOT NULL | — | No | The text of this chunk (~500 tokens). This is what gets embedded and what gets returned as context to Claude at query time. Never mix distilled and raw content in the same row — each row is one or the other. |
| `embedding` | `vector(1536)` | NOT NULL ⚠️ | — | No | The OpenAI `text-embedding-3-small` vector for this chunk's content. 1536 dimensions. **LOCKED — dimension count must never change without re-embedding all rows.** ⚠️ Verify NOT NULL is enforced in the Supabase dashboard before Phase 4. |
| `category` | `text` | — | NULL | Yes | Top-level classification (e.g., "Operations", "Sales", "HR"). Populated from the intake form dropdown. Used in source citations. |
| `subcategory` | `text` | — | NULL | Yes | Freeform subcategory beneath `category`. Set by the user at intake. Optional. |
| `industry` | `text` | — | NULL | Yes | Industry context (e.g., "Healthcare", "Manufacturing"). Set at intake. Useful for future filtered queries. |
| `doc_type` | `text` | — | NULL | Yes | Type of source document. Controlled vocabulary enforced by the intake form: `transcript`, `SOP`, `reference`, `case study`. No database-level CHECK constraint at this time — see Section 5. |
| `source` | `text` | — | NULL | Yes | Provenance of the document — e.g., a URL, filename, or meeting reference. Used alongside `title` to preserve parent document identity across chunks. Included in source citations. |
| `created_at` | `timestamptz` | NOT NULL | `now()` | No | Timestamp of row insertion. Set automatically by Supabase. |

## Index Definition

| Property | Value |
|---|---|
| Index type | `ivfflat` |
| Indexed column | `embedding` |
| Distance operator | `vector_cosine_ops` |
| `lists` parameter | **100** ⚠️ (assumed default — verify in Supabase dashboard) |
| Purpose | Approximate nearest-neighbor cosine similarity search |

**Notes:**
- ivfflat performs approximate (not exact) nearest-neighbor search. For small tables (under ~1,000 rows), a sequential scan may outperform the index. This is acceptable behavior.
- At query time, set `SET ivfflat.probes = 10` (or equivalent via Supabase query options) for better recall at a small performance cost. Default probes is 1.
- Do not drop or recreate this index without confirming all vectors are intact.

> ⚠️ **Verify:** Confirm the actual `lists` value used at index creation in the Supabase dashboard (`Database → Indexes`). If it differs from 100, update this document.

## Raw DDL

The SQL that produces (or would reproduce) the current schema:

```sql
-- Enable pgvector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- Documents table
CREATE TABLE documents (
  id            uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  title         text        NOT NULL,
  content       text        NOT NULL,
  embedding     vector(1536) NOT NULL,
  category      text,
  subcategory   text,
  industry      text,
  doc_type      text,
  source        text,
  created_at    timestamptz NOT NULL DEFAULT now()
);

-- ivfflat index for cosine similarity search
CREATE INDEX ON documents
  USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);
```

> ⚠️ The `NOT NULL` constraint on `embedding` must be verified against the actual Supabase table before Phase 4. If the column is nullable in production, update the DDL above and adjust the Python script accordingly.

## Supabase RPC Function

The chat app queries the knowledge base via a Supabase RPC function named `match_documents`. This function must be created in the Supabase SQL editor as part of Phase 5.

```sql
CREATE OR REPLACE FUNCTION match_documents (
  query_embedding  vector(1536),
  match_count      int DEFAULT 5,
  match_threshold  float DEFAULT 0.3
)
RETURNS TABLE (
  id          uuid,
  title       text,
  content     text,
  category    text,
  doc_type    text,
  source      text,
  similarity  float
)
LANGUAGE sql STABLE
AS $$
  SELECT
    id,
    title,
    content,
    category,
    doc_type,
    source,
    1 - (embedding <=> query_embedding) AS similarity
  FROM documents
  WHERE 1 - (embedding <=> query_embedding) > match_threshold
  ORDER BY similarity DESC
  LIMIT match_count;
$$;
```

**Parameters:**

| Parameter | Type | Default | Description |
|---|---|---|---|
| `query_embedding` | `vector(1536)` | required | The embedded form of the user's question |
| `match_count` | `int` | 5 | Maximum number of chunks to return |
| `match_threshold` | `float` | 0.3 | Minimum cosine similarity score; chunks below this are excluded |

## Row Level Security (RLS)

RLS is to be configured as part of Phase 5. The intended policy:

| Operation | Key type | Policy |
|---|---|---|
| `SELECT` | Anon key | Allowed — chat app reads via anon key |
| `INSERT` / `DELETE` | Service role key | Allowed — Python script uses service role key |
| All operations | Anon key | No insert/delete permitted |

**SQL to enable (execute in Supabase SQL editor during Phase 5):**

```sql
-- Enable RLS
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

-- Allow anon key to read (for chat app)
CREATE POLICY "Allow anon read"
  ON documents FOR SELECT
  TO anon
  USING (true);
```

> The Python script uses the service role key, which bypasses RLS entirely. No additional policy is needed for writes.

## Locked vs. Extensible

### Locked — Do Not Modify Without Full Re-embedding

These elements are frozen. Changing any of them invalidates all stored vectors and requires re-ingesting every document.

- `embedding` column type: `vector(1536)`
- Embedding model: `text-embedding-3-small` (implicit in every stored vector)
- The ivfflat index on `embedding`
- The `content` field semantics — what is stored must match what was embedded

### Extensible — Can Be Added With Approval

New columns and constraints can be added without invalidating existing embeddings:

- Additional metadata columns (see Section 8)
- CHECK constraint on `doc_type`
- Additional RLS policies
- Additional indexes on non-embedding columns

## Recommended Additions (Not Implemented — Require Approval)

These fields are not in the current schema. They are flagged as improvements worth considering before or after the initial build.

| Field | Type | Default | Rationale |
|---|---|---|---|
| `is_distilled` | `boolean` | `false` | Records whether this chunk came from a distilled or direct ingestion. Currently enforced by process only. A column makes this queryable and auditable. |
| `chunk_index` | `integer` | — | Sequential position of this chunk within the parent document (0-indexed). Needed if any future feature reconstructs full document context in order. |
| `token_count` | `integer` | — | Approximate token count for this chunk. Useful for debugging chunking behavior. |
| `doc_type` CHECK | constraint | — | Enforce `CHECK (doc_type IN ('transcript', 'SOP', 'reference', 'case study'))` to prevent garbage values. Currently enforced only at the form level. |

None of these are implemented. Do not add them without explicit approval.
